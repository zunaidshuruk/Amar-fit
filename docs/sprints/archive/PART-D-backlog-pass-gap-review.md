## ✅ PART D — NEW BACKLOG PASS (post-launch gap review)

Compiled from a fresh code review of the built app (not a screenshot review) — looking for gaps against a typically "complete" health/fitness/diet app, and for features that are silently half-built. Same rule as Part C: one scoped AI Studio prompt per item, do not combine.

1. [x] **Barcode scanning for packaged food** — verified fixed in commit `10ab400`. Adds a "Scan Meal" / "Scan Barcode" toggle at the top of `ScannerScreen.kt`; barcode mode runs on-device ML Kit detection (`BarcodeScanning.getClient()`) on the captured bitmap, then looks up the result against Open Food Facts (`AppRepository.lookupBarcodeProduct`), reusing the existing OkHttp client (now exposed as public instead of private) rather than a new one. Correctly falls back from per-serving to per-100g nutriment data when serving-size data isn't available, and labels which basis was used ("Per serving (X)" vs. "Per 100g — check the package for your actual portion") right in the description shown on the Scan Result card. Feeds into the exact same Scan Result review card, `MealTypeSelector`, and `logScannedFood` call already used by photo scans (carbsG/proteinG/fatG included) — zero changes to manual entry or photo-scan flows. Also added a safeguard beyond spec: "Log this meal" is disabled/relabeled "Dismiss" on an error/no-detection result so a failed scan can't get logged as 0-calorie food. Diff checked directly across all 4 changed files.
2. [x] **Water history drill-down chart** — verified fixed in commit `5fd4517`. Added a `waterLiters` case to `MetricDetailScreen.kt`'s metricKey dispatch (same shape as the existing carbsG/proteinG/fatG pattern, bar color from `AccentTokens.waterAccent(isDark).onBg`) and a matching "Water" `Triple` entry in `HealthScreen.kt`'s `additionalMetrics` list. No schema change needed — `waterLiters` was already logged and stored. Diff checked directly.
3. [x] **Surface badges in the UI** — verified fixed in commit `2d154af`. Also folded in `points` and `currentStreak`, which were in the same dead-feature state (computed in `TodayScreen.kt`, never rendered) — flagged this expansion to you before sending, you didn't object. New "Streak, Points & Badges" card added to `TodayScreen.kt`, placed exactly between the metric tiles grid and the Action Row as scoped: top row with streak (fire icon, "$currentStreak day streak" / "No streak yet") and points (star icon, formatted count) side by side, divider, then a "Badges" sub-section — empty-state text when none earned, otherwise a `FlowRow` of pill chips (icon + name) for each earned badge. Icon mapping matches spec exactly (Hydration Hero → water drop, 10k Steps Master → walk icon, Consistency Starter → calendar-check) with a generic trophy-icon fallback for any unmapped badge string, so a future badge type won't crash or render blank. Confirmed **zero changes** to `AppRepository.kt` — `checkAndAwardBadges` and the hardcoded 10k-steps threshold were correctly left untouched, exactly as scoped. Only `TodayScreen.kt` changed. Diff checked directly.
4. [x] **Language setting — descoped, removed instead of built.** Verified fixed in commits `4b1301b` (Settings) + `8fd8e45` (Auth) — both byte-for-byte identical to what was sent. Had the scoping conversation: real i18n was ranked out for now (biggest item in this tracker, and AI-generated content — Chat/Coach/Diet Chart/Workout — would need its own separate, much bigger pass regardless). Decision: rip out the non-functional pickers rather than leave a broken feature in the app, English-only until this is picked back up as its own deliberate project. Two direct fixes (not AI Studio, small/precise): (1) removed the "Language" row/dropdown from `SettingsScreen.kt`'s App Settings card, plus the dead `selectedLanguage`/`expandedLanguage`/`languages` state and its two write sites — confirmed no other file reads `profile.selectedLanguage`. (2) While checking that, found the **login screen had its own separate, actually-functional English/Bangla toggle** (`AuthScreen.kt`, a local `isBn` flag swapping auth-screen strings) — flagged it to you rather than silently touching or leaving it; you said remove it too for consistency. Replaced every `if (isBn) ... else ...` with the English string directly, removed the toggle state and the TopAppBar dropdown UI, removed the now-unused `Language` icon import.
