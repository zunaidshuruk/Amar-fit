## 🔲 PART R — COMPLETE DESIGN OVERHAUL, FITPAL-INSPIRED MINIMALIST DARK THEME (Phase 0 + Phase 1 verified, Phase 2 prompt sent — started ahead of Part Q, per Zunaid)

Zunaid's request: redesign the entire app (all 26 screens) to a minimalist dark aesthetic, referencing the "Fitpal" Envato Elements UI kit (dark near-black backgrounds, lime-green accent, rounded cards, clean data-viz). Screenshots of the kit's splash/onboarding/home/activity/chat screens and its color+typography style guide were reviewed directly.

**3 architecture decisions confirmed with Zunaid before scoping anything:**
1. **REVISED — collapse to a single signature accent: lime green (`#BEF264`, the FitPal reference's own accent).** Originally decided the opposite (keep every metric's own color, adopt only the reference's layout/spacing/typography) — reversed after Zunaid compared FitPal against a second dark-theme reference (a gold/amber-accented ride-hailing app kit) and asked which was more accessible. Contrast-ratio math against the app's near-black background (`#121212`) favored lime green (~14:1) over the gold/amber alternative (~9-11:1 depending on exact shade) — both clear WCAG AAA (7:1), but lime has meaningfully more headroom, which matters most for small text/icons/chart lines and for users with reduced contrast sensitivity. Zunaid picked lime on that basis.
   **Carve-out — REVISED again: alert/semantic colors also consolidate, into one amber.** Originally the plan was to leave the existing distinct alert colors alone (red for over-limit calories, orange for resting-heart-rate alerts). Zunaid instead asked to replace both of those with a single unified warning color from the same gold/amber range considered above (`#F5A623`–`#FFC107`), used as a full replacement rather than a middle tier alongside a separate red. Picked **`#F5A623`**: clears WCAG AAA against `#121212` at ~9.25:1, and at ~37° hue sits further from lime's ~82° hue than `#FFC107` (~45°) would — the wider hue gap matters because red-green color blindness (the most common form) can make amber and lime drift toward the same yellow-brown, which would undercut the whole point of alerts needing to read as visually distinct from the branding accent. Final palette is two-tier: lime `#BEF264` for decorative/branding accents, amber `#F5A623` for every alert/warning state (over-limit calories, resting-HR alerts, and any other error/danger UI currently on `Red500`/`Orange700`) — not a three-tier lime/amber/red system.
   **REVISED a third time (this session) — exact base colors replaced.** Zunaid shared a color-palette reference card and asked to use it as the base: background is now **Gun Metal `#00272b`** (a dark teal-black, replacing the neutral near-black `#121212`), and the signature accent is now **Chartreuse `#e0ff4f`** (replacing lime `#BEF264`). Contrast checked the same way as before: Chartreuse on Gun Metal is **~14.0:1**, essentially matching the prior lime-on-near-black pairing's headroom (~14.3:1) — still comfortably clears WCAG AAA (7:1). The existing amber alert color (`#F5A623`) was re-checked against the new Gun Metal background too: **~7.8:1**, still clears AAA but with noticeably less headroom than before (was ~9.25:1 against `#121212`) — not currently a problem, but worth knowing if amber is ever paired with small text on the new background. Zunaid did not ask to change the alert color, so it stays `#F5A623` unless revisited. **Not yet decided:** whether Gun Metal `#00272b` becomes the single flat background (replacing the whole `#121212`/`#1E1E1E`/`#262626` elevation ramp from the Part B redesign) or just the base of a new ramp with lighter Gun-Metal-derived tones for `surface`/`surfaceVariant` — this wasn't specified and should be confirmed (or judgment-called) when Part R's Phase 0 is actually scoped, not invented now.
   **REVISED a fourth time (this session) — secondary color added.** Zunaid shared a third color-reference card and asked to add **Iron `#CDD2D7`** (a light warm gray) as an additional **secondary** color alongside the Gun Metal background and Chartreuse primary accent. Contrast checked the same way as the prior two: Iron on Gun Metal is **~10.4:1**, comfortably clearing WCAG AAA (7:1) — usable as secondary text/icon/UI color directly on the app's background. (For completeness: Iron directly on Chartreuse is only **~1.4:1** — essentially unreadable — so Iron should not be used as text/foreground on top of Chartreuse-filled elements; this only matters if a future screen stacks the two, which nothing currently scoped does.) **Not yet decided:** exactly which UI role Iron fills (secondary/muted text? inactive icons/nav states? card borders/dividers?) — Zunaid designated it "secondary" but the specific call sites haven't been discussed, so this stays open for Phase 0 scoping rather than being invented now. Base palette for Part R is now three colors: Gun Metal `#00272b` (background), Chartreuse `#e0ff4f` (primary/signature accent), Iron `#CDD2D7` (secondary).
2. **Dark mode only.** Drop the light theme entirely — matches the reference (it only shows a dark theme).
3. **Keep the system font**, just apply the reference's type scale (sizes/weights) rather than bundling the reference's actual "Satoshi" font. Simpler, lower-risk, avoids a new font-asset/licensing surface.
