## 🔲 PART S — URGENT BUG FIX: near-invisible dialog button text in dark mode (reported by Zunaid, jumped the queue ahead of Part P #8 Phase 1)

Zunaid reported the "Cancel"/"Send Reset Link" buttons on the Forgot Password dialog were essentially invisible in dark mode (screenshot showed only ghost-faint text), and said the same happens on Log Out and "most of the options."

**Root cause found (this session), not a prompt-scoped patch job — a single-line theme fix:** `Theme.kt`'s `DarkColorScheme` sets `primary = Primary`, and `Primary` (`Color.kt`) is `#1B4528` — a very dark forest green designed to read as dark text on a light background. It was reused verbatim in `DarkColorScheme` instead of being swapped for a light-mode-appropriate value, so in dark mode it computes to roughly **1.5–1.7:1 contrast** against the app's `#121212`/`#1E1E1E` backgrounds — nowhere close to WCAG's 3:1 floor for UI components, i.e. genuinely near-invisible, exactly matching the screenshot.

This one value is the default content color for any `TextButton` that doesn't explicitly override its color — confirmed via `AuthScreen.kt`'s Forgot Password dialog (`TextButton(onClick = ...) { Text("Send Reset Link") }` / `Text("Cancel")`, no color override, exactly matching the report) — and grepping the codebase found **50 `TextButton` call sites across 15 files** relying on this same default, plus several explicit `MaterialTheme.colorScheme.primary` foreground usages in `MetricDetailScreen.kt` (selected tab/legend text+icon), `WorkoutSessionScreen.kt` (icons/text), `MindfulnessTimerScreen.kt`, and `ExerciseImageDemo.kt` — all currently suffering the identical near-invisible bug, which explains "most of the options."

**Confirmed zero regression risk from fixing this at the theme level, not per-call-site:** every filled `Button(...)` in the app (checked all ~16 non-tab-toggle instances) already passes an explicit `colors = ButtonDefaults.buttonColors(containerColor = ...)` — none rely on the default primary-background/onPrimary-content pairing — and `colorScheme.secondary` has zero usages anywhere in the codebase. So changing `DarkColorScheme.primary` only affects the currently-broken foreground text/icon cases; nothing currently correct changes.

**Fix — [x] verified fixed in commit `89ea5a0`.** `Theme.kt`'s `DarkColorScheme.primary` changed from `Primary` (`#1B4528`) to `Secondary` (`#2ECC71`, already defined in `Color.kt` as "Leaf green identity," already used for `secondary` in the very same scheme) — contrast against `#121212` is ~8.9:1, comfortably clearing WCAG AAA. Diff is exactly the one line specced (`primary = Primary,` → `primary = Secondary,`, comment updated), `LightColorScheme` untouched, nothing else in the file touched, brace/paren balance and duplicate-import checks clean, `debug.keystore` unchanged. Diff checked directly. **This should fix every dialog Cancel/Confirm button across the app (Reset Password, Log Out, Delete Account, Change Password, Change Email, etc.) plus the other near-invisible foreground usages found in `MetricDetailScreen.kt`/`WorkoutSessionScreen.kt`/`MindfulnessTimerScreen.kt` — worth Zunaid confirming visually on a real device/emulator that the Reset Password and Log Out dialogs now read clearly.**

**Second urgent fix (this session) — header name overflow.** Zunaid reported (via screenshot) the "Good Evening, Zunaid Hossain" header text on the Today screen running under the sync icon and profile picture. Root cause: `MainActivity.kt`'s shared `TopAppBar` (used by all 5 main tabs) builds `"$greeting, $name"` from the full stored profile name with no `maxLines`/`overflow` set. **[x] verified fixed in commit `1d56176`.** `name` now derives just the first word of the stored name (`(userProfile?.name ?: "Guest").trim().split(" ").firstOrNull { it.isNotBlank() } ?: "Guest"`), and the greeting `Text` gained `maxLines = 1` + `overflow = TextOverflow.Ellipsis` as a safety net. The avatar's initial-letter fallback (still derived from the full name) and the "HEALTH & DIET" label are both confirmed untouched. Only `MainActivity.kt` changed (12 lines), `debug.keystore` untouched. Diff checked directly.

The nutritional-deficiency alert call site in `ShasthoViewModel.kt` confirmed untouched (no `targetRoute` added there, matching spec), `GlucoseLogScreen.kt` confirmed untouched by this commit. `debug.keystore` unchanged, checksum still matches. Brace/paren balance and duplicate-import checks clean across all 3 Kotlin files. Diff checked directly, symbol-by-symbol.
