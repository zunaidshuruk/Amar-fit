- [x] **Health Connect permission UX + hydration sync failure** — verified fixed in commit `c3db194`. Root cause was: the "Connect" button always requested the full permission set with no check for what's already been decided; once Android permanently denies a specific health permission, it silently stops showing that permission's prompt on future requests, so the user never learns why 2 permissions stayed stuck denied. Fix adds stuck-denied detection in `SettingsScreen.kt` with a button that opens Health Connect's own permission settings, a success/failure callback on `addWater()` instead of swallowing errors, and a Toast in `TodayScreen.kt` on sync failure (reusing the existing sync-failure-visibility pattern). One accepted deviation from the original 2-dialog spec: AI Studio merged the two distinct permission-failure messages into a single dialog instead of two — reasonable, not worth a rework. Diff checked directly.
