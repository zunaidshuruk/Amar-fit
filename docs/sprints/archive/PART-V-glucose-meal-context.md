## 🔲 PART V — BLOOD GLUCOSE MEAL-CONTEXT TRACKING & AI GLUCOSE GUIDANCE (new sprint, in progress)

Zunaid's request, kept as its own sprint per his explicit instruction: (1) track blood glucose Before and After Breakfast, Lunch, and Dinner (6 readings/day, replacing the current coarse Morning/Night model); (2) the Blood Glucose target range shown on the chart (Part U Phase 3) is **user-set under Health Goals**, not a standard clinical default; (3) a new AI feature that looks across *all* health metrics (not just glucose) and suggests how to lower blood glucose. This absorbed Part T's original, simpler Blood Glucose phase (specimen source + auto-derived Morning/Night relation-to-meal + first HC write) once the richer 6-reading model was requested — that plan is superseded by what's below.

**Current data model (confirmed this session):** `DailyMetric.bloodGlucoseMorning`/`bloodGlucoseNight` (2 floats), set via `ShasthoViewModel.setBloodGlucoseMorning`/`setBloodGlucoseNight`, edited in `GlucoseLogScreen.kt` (2 plain number fields, labeled "Fasting (Morning)"/"Post-Meal (Night)"), never written to Health Connect (read-only permission only). HbA1c is estimated in `GlucoseLogScreen.kt` from the average of all Morning/Night values across `metricsHistory` (90 days).

**Bug found and being fixed as part of Phase 1 (already flagged when Part T first researched this):** `ShasthoViewModel.kt`'s Health-Connect sync reads a synced glucose value with `.inMilligramsPerDeciliter` and stores it straight into `bloodGlucoseMorning`, but manual entry and the HbA1c formula both assume mmol/L — a real unit-mismatch bug, fixed in Phase 1 since it's the same code path the new write logic has to touch anyway.

**Design decisions made this session (stated plainly since several were judgment calls, not directly specified):**
- Old `bloodGlucoseMorning`/`bloodGlucoseNight` fields are **kept, not removed or migrated** — additive-only, no data loss, consistent with every other schema change this sprint. The 6 new fields are the going-forward model; Phase 2's UI redesign will decide how (or whether) the old two are still shown.
- **Specimen source is one field per day**, not per-reading (`bloodGlucoseSpecimenSource`, same "Not set" default pattern as Blood Pressure's new fields) — a person realistically uses the same glucometer/test type for all of a day's readings, so a single selector avoids 6x UI clutter for no real benefit.
- **Meal type/relation-to-meal are derived automatically from which of the 6 functions is called**, not a separate UI selector — "Before Breakfast" unambiguously means `MealType.MEAL_TYPE_BREAKFAST` + `RELATION_TO_MEAL_BEFORE_MEAL`, so asking the user to also pick a meal type would be redundant.
- **No auto-calculation for the Health Goals target range** — unlike Steps/Water/Calories (which have real BMR/activity-level formulas), there's no formula for a personalized glucose target from profile data, so this is manual-only, matching the precedent set by Part O's Body Measurements (also manual-only, no fake "auto" toggle).
