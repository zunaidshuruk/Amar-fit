## ✅ PART M — GOOGLE DRIVE BACKUP/RESTORE — complete

User request: let the user save all their app data to their own Google Drive, and pull it back to restore/sync later. Scoped as **additive to Firestore, not a replacement** — Firestore keeps handling multi-device sync as-is; Drive is a separate, user-owned backup copy. Trigger is **manual only** (Backup Now / Restore buttons in Settings), not automatic — confirmed with Zunaid.

**Zunaid's own prerequisite (not an AI Studio item):** enable the "Google Drive API" for the project in Google Cloud Console (APIs & Services → Library). Code will compile/push without this; the backup button will just fail at runtime until it's on. Not blocking the prompt going out.

Technical grounding (this session): zero new Gradle dependencies needed — `play-services-auth` (for the `drive.file` OAuth scope via `Identity.getAuthorizationClient`), Moshi (`RetrofitClient.moshi`, already reflection-based so existing Room entities serialize with no new annotations), and Retrofit (mirroring `YouTubeClient.kt`'s second-base-URL pattern) are all already in the project. "All the app's data" = the same 7 things `FirebaseManager.pullDataOnLogin` already syncs: profile, daily_metrics, food_logs, saved_diet_charts, saved_workouts, saved_chats, medical_records.
